## Questions

3. Why do eight hexadecimal zeros represent 32 bits?

5. In `P = k × G`, which value is the private key?

## Arjun's answers

### 1. Double spending

> What stops someone from spending the same Bitcoin output twice? UTXOs. But the fundamental design in Bitcoin is that an output can only be spent once. The moment you spend Bitcoin related to an address, you have to use the full Bitcoin in that address. So normally you pay someone and you send the remaining to a change address. So that output after that is not part of the UTXO list. You cannot spend it anymore because there's no Bitcoins in that output. That's one of the ways they protect against double spending.

### 2. Change

> Second question: an input is 1 BTC, the payment is 0.3 BTC, the fee is 0.01 BTC. The change is the input minus the output plus and fee together. So the output is 0.3, the fee is 0.001. You add those two and you subtract it from 1 BTC. That's the fee.

### 3. Hexadecimal zeros

> Why do 8 hexadecimal zeros represent 32 bits? Each 32 bits, okay? Let's look at what is in one hexadecimal. One hexadecimal is equal to 4 bits. So 8 hexadecimal zeros is equal to 32 bits. That's 8 into 4.

### 4. Merkle proof

> Does a Merkle proof also prove that a transaction is valid? That's the next question, and the answer to that is: does a Merkle proof also prove that a transaction is valid? Not really. I mean, there are different consensus rules to check if a transaction is valid. The Merkle proof actually shows that that transaction belongs in the block hash, in the transaction block hash. It's just a way to prove easily without storing all those transactions that this transaction was present at the time the hash was created.

### 5. Private key

> If P is equal to K into G, what value is the private key? The G is the generator, the K... I think the private key is K.

## AI reply

### 1. Double spending

Your main idea is correct. The key correction is **output, not address**.
An address can have several unspent outputs.
You must spend each selected output in full.
You do not have to spend every output associated with that address.

The spent output remains in the transaction history.
It leaves the set of unspent outputs.
Nodes reject any later transaction that tries to spend it again.
Bitcoin's chain selection rules help nodes agree on which conflicting spend is accepted.

### 2. Change

Your calculation method is correct.
You mentioned both `0.01` and `0.001 BTC`.
Using the question's fee of `0.001 BTC`:

```text
Change = input − payment − fee
       = 1 − 0.3 − 0.001
       = 0.699 BTC
```

You called the result “the fee” at the end. It is the **change**.

### 3. Hexadecimal zeros

Correct. One hexadecimal **digit** represents four bits.
Therefore, eight digits represent `8 × 4 = 32 bits`.

### 4. Merkle proof

Correct distinction.
It proves that a transaction is included in the set represented by a particular **Merkle root**.
The block header contains that root.

The proof does not check the transaction's signatures or spending rules.
You must also check that the block header belongs to the accepted blockchain.
Say “Merkle root” instead of “transaction block hash.”

### 5. Private key

Correct. In `P = k × G`:

- `k` is the private key: a number.
- `G` is the fixed generator point.
- `P` is the public key: the resulting point.

That completes today's review.
The main correction to retain is: **Bitcoin spends individual outputs, not an address's whole balance.**
